discorddol.base¶

Core of discorddol: a Discord read backend and the Mapping stores over it.

The design has one hinge: the backend. Everything user-facing is a Mapping whose data comes from a backend object exposing five methods – guilds, channels, threads, archived_threads, messages – each returning plain JSON-able dicts. The default backend (DiscordRest) talks to the live Discord API; swapping it for one that reads a Discord data export, or a dict of fixtures, changes nothing above it.

The stores:

Guilds()                       # Mapping: guild name/id -> Channels
Channels(guild_id)             # Mapping: channel name/id -> list of message dicts
Channels(guild_id).info        # Mapping: channel name/id -> channel metadata

so the common case reads like plain Python:

from discorddol import Guilds

msgs = Guilds()['Example Guild']['feedback']

DiscordRest uses discord.py in REST-only mode – it logs in over HTTP but never opens a gateway connection. That makes every call a one-shot fetch that returns promptly, instead of a bot process you have to keep alive and shut down.

class discorddol.base.Channels(guild_id, *, backend=None, token=None, cache_store=None, include_threads=False, **message_kwargs)[source]¶

Bases: Mapping

Mapping of one guild’s channels: key -> list of message dicts.

Keys are channel names when unambiguous, and channel ids otherwise. Lookup accepts either form, plus a leading #, so channels['#dev'] and channels['dev'] and channels['10'] all work.

A forum or a category has no messages of its own, so it maps to an empty list; with include_threads=True a forum maps to the messages of its posts.

>>> backend = DictBackend(
...     channels={'1': [{'id': '10', 'name': 'dev'}, {'id': '11', 'name': 'feedback'}]},
...     messages={'10': [{'id': '100', 'content': 'hi'}]},
... )
>>> channels = Channels('1', backend=backend)
>>> sorted(channels)
['dev', 'feedback']
>>> channels['dev']
[{'id': '100', 'content': 'hi'}]
>>> channels.info['dev']['id']
'10'

In-memory backend over plain dicts. Real enough for tests, fixtures and exports.

>>> backend = DictBackend(
...     guilds=[{'id': '1', 'name': 'Example Guild'}],
...     channels={'1': [{'id': '10', 'name': 'dev'}]},
...     messages={'10': [{'id': '100', 'content': 'hi'}]},
... )
>>> backend.guilds()
[{'id': '1', 'name': 'Example Guild'}]
>>> backend.messages('10')
[{'id': '100', 'content': 'hi'}]

The threads under channel_id marked archived: public, or private ones.

>>> backend = DictBackend(threads={'10': [
...     {'id': '20', 'type': 'public_thread', 'archived': True},
...     {'id': '21', 'type': 'private_thread', 'archived': True},
...     {'id': '22', 'type': 'public_thread'},

messages(channel_id, *, limit=None, after=None, before=None, oldest_first=True, **kwargs)[source]¶

Stored messages, filtered the way DiscordRest.messages() filters them.

Messages are stored oldest first. after and before take a message id, compared as a Discord snowflake (an integer), or a datetime, compared with each message’s created_at. Other keyword arguments are accepted and ignored.

>>> backend = DictBackend(messages={'10': [{'id': '1'}, {'id': '2'}, {'id': '3'}]})
>>> [m['id'] for m in backend.messages('10', after='1', limit=1)]
['2']
>>> [m['id'] for m in backend.messages('10', oldest_first=False, limit=1)]
['3']
Return type:

list[dict]

archived_threads(channel_id, *, private=False)[source]¶

List a channel’s archived threads: the public ones, or the private ones.

Listing private archived threads needs the Manage Threads permission; without it Discord answers 403, raised as Forbidden. Only text channels hold private threads, so private=True on any other channel returns an empty list.

send_message(channel_id, text, *, allowed_mentions=None, reply_to=None)[source]¶

Post a message to a channel. The one write operation; needs Send Messages.

Read access is what discorddol is for – this exists so that acting on what you read does not require a second library.

Parameters:

  • allowed_mentions (Any) – which mentions in text Discord may turn into pings: a discord.AllowedMentions or a dict such as {"everyone": False, "roles": False, "users": ["123"]} (users and roles take True/False or a list of ids). The default, DFLT_ALLOWED_MENTIONS, blocks @everyone, @here and role mentions, so relaying quoted text cannot ping a whole server.

  • reply_to (Optional[str]) – id of a message in this channel to answer (a Discord reply).

Return type:

dict

discorddol.base.channel_kind(record)[source]¶

The kind of a channel record: 'text', 'announcement', 'forum', …

A record without a type counts as a text channel, which is what a hand-written fixture usually means. An unknown type comes back as it is.

>>> channel_kind({'type': 'news'})
'announcement'
>>> channel_kind({'type': 'ChannelType.stage_voice'})
'stage'
>>> channel_kind({'id': '10'})
'text'

discorddol.base.message_to_dict(message)[source]¶

Serialize a discord.Message to a plain, JSON-safe dict.

A message that is only a sticker, a poll or a forward has no text, attachments or embeds of its own, so those live under stickers, poll (None when the message has none) and forwarded (one entry per forwarded message, which is how Discord holds a forward: a snapshot of the original).

Return type:

dict
